# Plan: SPI2 de usuario del ESP32-S3

**Objetivo y especificación:** fase 6d solicitada: Arduino 3.3.12 / IDF 5.5,
SPI2 CPU y GDMA, MOSI exacto en bus 2 del puente v7, MISO FF.
**Arquitectura:** reutilizar `esp32c3_spi2.c` con configuración S3: cinco
canales, SRAM DMA `0x3FC88000..0x3FD00000` y registro INT_SET en `+0x44`.
Tipo QOM S3 derivado del C3; SPI1 de flash independiente. Conservar mapa
GDMA S3 de Espressif, corrigiendo pulsos STOP/reset en su adaptador.
**Restricciones:** solo este worktree `fase6d-s3-spi`; sin commits ni cambios
en VERSION o workflows. Direcciones DMA absolutas (E-046); máscaras de más
de 31 bits con tipos de 64 bits (E-045).

## Foco de revisión

- INT_SET S3 despierta primera ISR; RAW y CLR no pierden eventos pendientes.
- Canal 4 funciona; canales parados o destinados a otro periférico no se usan.
- SRAM alta S3 y bordes no permiten MMIO/flash; dobles reciben direcciones absolutas.
- Cada USR vacía transacción; DMA no repite bytes sin START nuevo.
- STOP/reset no dejan canales bloqueados al reutilizar spi_master.

## Evidencia inicial

Árbol base leído por UNC de WSL; lanzar WSL falla con E_ACCESSDENIED.
Mapa S3 coincide con `soc/gdma_reg.h`, `gdma_struct.h`, `hal/gdma_ll.h`
locales: canales a stride 0xc0, OUT +0x60, LINK +0x20, IRQ +0x08..0x14,
PERI_SEL +0x48. Modelo genérico no autolimpia STOP ni cancela START al reset.
SPI comparte registros usados, pero HAL S3 escribe INT_SET para lanzar ISR;
C3 escribe RAW. FSPICLK=101, FSPID=103, frente a 63/65 en C3.
Base: 121 pruebas, 110 correctas con MSVC y 11 omisiones heredadas.
